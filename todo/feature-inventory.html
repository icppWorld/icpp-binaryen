Detail

What each feature covers

01 initial-package done

The 116.0.0 package itself: hand-curated cffi cdef, Module wrapper, fix_globals_limit, unit + smoke pytest suites, the byte-identical parity gate against binaryen.py==0.0.2, per-platform wheel CI, and the tag-triggered trusted-publishing release workflow.

Branch: feature/initial-package Gate: parity golden test/parity/golden-116.json PR: icpp-binaryen#1

02 llama-migration done

Phase 1 (HANDOVER §4): llama_cpp_canister replaces binaryen.py==0.0.2 with icpp-binaryen==116.0.0 in requirements.txt and docker/docker-compose.yml; scripts/optimize_wasm.py shrinks to a thin fix_globals_limit call; the Dockerfile.base relink + sed hack is deleted (host-side Linux builds start working). Also lands the downstream-verify-api / downstream-verify-full make targets in this repo. Merged 2026-09-21: icpp-binaryen #3 and llama #33, shipped in llama v0.18.0. Byte-identical: no new WASM-HASHES row, verified by rebuild.

Depends on: 01 released Repos: llama_cpp_canister + this repo

03 icpp-pro-integration planned

Phase 2: icpp-pro adds icpp-binaryen as a lockstep-pinned dependency and icpp build-wasm runs fix_globals_limit as a built-in post-link step — after wasi2ic, before the user's post_wasm_function — behind an on-by-default fix_globals_limit = true flag in icpp.toml. The _before_opt backup becomes an icpp-pro convention; ordering contract documented in icpp-docs.

Depends on: 02 merged Pin check: make -C ../icpp-pro check-sibling-pins

04 binaryen-132-bump planned

A deliberate major release bundling Binaryen 132 (or newer). The emitted wasm bytes change, so this carries the full downstream hash-change ceremony: a new WASM-HASHES row via llama_cpp_canister's release process and, once Phase 2 has landed, an icpp-pro release. The parity golden is re-established for the new major.

Output bytes: hash-changing Needs explicit maintainer sign-off in the plan

05 cleanup planned

Phase 3: llama_cpp_canister deletes scripts/optimize_wasm.py and the post_wasm_function line from icpp.toml (the built-in Phase 2 step covers it), and the dormant icppWorld/binaryen.py fork is archived.

Depends on: 03 merged

Ceremony

How this inventory is maintained

Rules from README-feature-guide.md, Ceremonies 1 & 6:
  • Two synchronized places: this file and its published Claude artifact (URL in todo/artifacts.md). Every edit updates the file AND republishes the artifact in the same sitting.
  • Statuses reflect merge state: an open PR marks an item in progress / in review (with the PR links), never done. Done happens only after every PR of the feature has merged, as a roadmap-only commit on main plus republish.
  • Split items keep the parent id (e.g. 02a / 02b) — no renumbering, so history and references stay stable.
